## 25. 費用の考え方

確認：2026年9月

料金は頻繁に変わるため、金額は記載しない。採用前に各サービスの料金ページで最新の金額を確認する。ここでは**何に対して課金され、どこで膨らみやすいか**を整理する。

```cost
rows:
  - service: Vercel
    tools: [vercel]
    axis: 関数の実行（アクティブなCPU時間、メモリ、呼び出し回数）、画像最適化の変換回数、データ転送、ビルド
    grows: 画像最適化・SSRの多用、アクセス急増
    action: 支出上限を設定する。静的生成できるページは静的にする
  - service: Supabase
    tools: [supabase]
    axis: コンピュート（インスタンスサイズ）、月間アクティブユーザー数、データ転送量、ストレージ
    grows: toCでのユーザー増加、Storageからの大量配信
    action: 画像や動画の配信はCDN（Cloudflare Images等）に逃がす。規模が見えたら §24 の移行パスを検討する
  - service: Neon
    tools: [neon]
    axis: コンピュート時間、ストレージ
    grows: 常時起動の設定、使っていないブランチやプロジェクトの放置
    action: 自動停止（scale to zero）を有効にする。不要なブランチを削除する
  - service: Amazon RDS
    tools: [amazon-rds-for-postgresql]
    axis: インスタンスの稼働時間、ストレージ、I/O、バックアップ
    grows: 過大なインスタンスサイズ、使っていない検証環境の常時稼働
    action: 検証環境は夜間停止する。リザーブドインスタンスを検討する
  - service: ECS Fargate
    tools: [ecs-on-fargate]
    axis: vCPU・メモリの稼働時間
    grows: 過大なタスクサイズ、最小タスク数の設定しすぎ
    action: 実測に合わせて調整する。検証環境はSpotを使う
  - service: AWS Lambda
    tools: [lambda]
    axis: リクエスト数、実行時間×メモリ（初期化にかかった時間も課金対象）
    grows: 常時トラフィックをLambdaで処理している
    action: §23-2 の目安で常駐コンテナへ移す
  - service: NAT Gateway
    tools: [nat-gateway]
    axis: 稼働時間、処理したデータ量
    grows: プライベートサブネットからの外部通信量（イメージ取得、外部API）
    action: VPCエンドポイントを使う。検証環境では構成を見直す
  - service: S3
    tools: [s3]
    axis: 保存量、リクエスト数、データ転送
    grows: 外部への大量配信
    action: CloudFront経由で配信する。配信が多いならR2を検討する
  - service: Cloudflare R2
    tools: [cloudflare-r2]
    axis: 保存量、操作回数（外部への転送は無料）
    grows: 大量の小さなファイル操作
    action: まとめて扱う
  - service: CloudWatch
    tools: [cloudwatch]
    axis: ログの取り込み量、保存期間、Logs Insightsでスキャンした量、カスタムメトリクス
    grows: デバッグログの出しっぱなし、保存期間を無期限のままにする
    action: ログレベルと保存期間を決める。参照頻度の低いロググループは低頻度アクセスのクラスにする
  - service: Datadog
    tools: [datadog]
    axis: ホスト数、ログ量、カスタムメトリクス
    grows: ログの全量送信、タグの組み合わせ爆発
    action: 送信するログを絞る。サンプリングを使う
  - service: Sentry
    tools: [sentry]
    axis: エラー数、トレースのスパン数、セッションリプレイ数、ログ量
    grows: 同じエラーの大量発生、トレースの全量送信
    action: トレースのサンプリング率を設定する。既知のノイズを除外する
  - service: Clerk／Auth0
    tools: [clerk, auth0]
    axis: 月間アクティブユーザー数
    grows: toCでユーザーが急増
    action: 規模が見えたら §24 の移行パスを検討する
  - service: Algolia
    tools: [algolia]
    axis: 検索リクエスト数、レコード数
    grows: 入力のたびに検索する実装
    action: デバウンスを入れる。規模次第でMeilisearchを検討する
  - service: LLM API
    axis: 入出力のトークン数
    grows: 長いプロンプトの繰り返し送信、不要な再生成
    action: プロンプトキャッシュを使う。用途ごとに小さいモデルを使い分ける
  - service: Stripe／KOMOJU
    tools: [stripe, komoju]
    axis: 決済額に対する手数料率
    grows: —
    action: 決済手段ごとの料率を事前に確認する
```

**共通の対策**：クラウドの予算アラートを必ず設定する。PaaSは支出上限を設定する。検証環境は使わない時間に停止する。
